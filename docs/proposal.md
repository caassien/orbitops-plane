## 一、项目名称

OrbitOps Plane：MoonBit 平台无关变更决策内核

## 二、项目简介

OrbitOps Plane 是一个无副作用、可嵌入的 MoonBit 库。宿主提供期望状态、观测状态、资源依赖与安全策略，库输出确定性的差异动作、依赖有序计划、执行批次、审批要求和可重放审计事件。它负责执行前的变更决策，不负责节点发现、网络调用、凭据管理、持久化、调度器或控制台；真实副作用仍由宿主执行。因此它可作为 MoonFlow、LunaNexa 或其他 MoonBit 控制面的公共窄内核。

## 三、项目方向与通用性说明

MoonBit 已有 `vectie/lunanexa` 这类完整产品控制面和 `vectie/moonflow` 这类持久化编排引擎，但缺少一个可被多个宿主复用的纯变更决策层。每个平台若自行实现状态比较、依赖排序、风险策略、预算、过期状态保护和审计，容易出现规则不一致，也必须在真实集群中才能完整验证。本项目补齐“平台无关、可嵌入、可重放”的决策内核位置，通用性不依赖 Kubernetes、SSH、云厂商 API 或特定运维平台。

## 四、预期使用场景

1. **依赖感知发布**：宿主给出 `database/primary -> service/api -> worker/jobs`。相同输入必须生成相同顺序，循环依赖直接拒绝，并在单资源批次预算下依次执行和形成审计记录。运行 `moon run cmd/demo -- rollout` 可复现。
2. **配置漂移修复**：比较期望配置与观测配置，只生成必要动作；若观测 generation 落后于计划基线，执行前拒绝旧计划，避免依据过期状态完成变更。运行 `moon run cmd/demo -- drift` 可复现。
3. **故障处置保护**：批量重启、删除和关键资源配置为高风险；核心要求显式审批，并在执行器返回失败后停止后续操作。每次策略决定、审批、反馈和终止均有稳定审计事件。运行 `moon run cmd/demo -- incident` 可复现。

## 五、拟实现的核心功能

- 类型安全的资源、期望状态、观测状态、操作、计划和执行反馈模型。
- 确定性 `compute_diff`，支持创建、更新、扩缩容、重启、删除和未知动作 fail-closed。
- 依赖图校验、循环依赖拒绝、稳定的依赖优先排序和删除反向排序。
- 可解释安全策略、风险分级、关键资源保护、审批状态机和变更预算。
- generation 保护、重复反馈拒绝、调和生命周期和可重放审计事件。
- 内存执行器和三个端到端示例；当前 72 个测试，CI 覆盖格式、构建、测试和接口生成。
- `0.2.0` 稳定宿主适配接口和计划/审计序列化边界，并发布到 mooncakes.io 模块 `caassien/orbitops_plane`。

## 六、原创或移植说明

本项目为原创 MoonBit 实现，不移植、复制或改写其他语言的开源项目。实现中不包含第三方源代码；参考的 Kubernetes Controller、Terraform Plan 和 LunaNexa 仅用于职责边界比较，不复制其代码、数据模型或许可证内容。

## 七、实现路径与技术理解

计划生成保持纯函数和确定性：输入数组顺序不能改变结果，独立资源按稳定 key 排序，依赖边统一采用 `(dependency, dependent)` 语义。执行采用“计划、校验、执行、反馈”四阶段，执行前再次校验 generation，高风险策略先于执行器生效。该设计的关键不是重做控制器，而是把容易产生分歧的决策规则收敛到一个可独立测试的 MoonBit 库。

## 八、交付范围与明确不做项

交付决策模型、差异计算、依赖规划、批次预算、安全策略、生命周期、审计重放、测试和示例。明确不提供服务器、远程 Agent、SSH/Kubernetes SDK、云厂商 SDK、凭据管理、持久化数据库、UI、监控系统或大模型自动执行，也不承诺替代 Terraform、Kubernetes Controller、LunaNexa 或 MoonFlow。

## 九、与 LunaNexa 的对比说明

LunaNexa 是模型即服务与硬件集群产品控制面，负责节点清单、运行时适配、部署、放置、回滚、API、持久化和控制台。OrbitOps Plane 不复制这些职责，也不接收模型、节点或真实凭据；它只把“期望状态到变更计划”抽成可单元测试的 MoonBit 内核。LunaNexa 或其他宿主可继续拥有资源状态、执行方式和交付策略，同时复用本库的稳定排序、风险审批、预算、过期保护和审计重放。

## 十、验收标准

1. 三个 demo 与 72 个测试可复现，核心路径均有失败场景覆盖。
2. 相同输入及不同输入排列产生相同计划；循环依赖、过期计划和重复反馈必须显式失败。
3. 高风险操作在无审批时不得进入执行；执行失败后不得继续后续动作。
4. 每次允许、拒绝、审批、执行反馈和终止均可从审计流重放得到相同状态。
