# OrbitOps Plane：MoonBit 变更决策内核

GitHub：https://github.com/caassien/orbitops-plane

## 项目简介

OrbitOps Plane 是一个原创、平台无关、无副作用、可嵌入的 MoonBit 库。宿主提供期望状态、观测状态、资源依赖与安全策略，库输出确定性的差异动作、依赖有序计划、执行批次、审批要求和可重放审计事件。真实执行仍由宿主完成，因此它不与 LunaNexa 争夺节点、模型运行时、HTTP API、持久化或控制台职责。

## 痛点与生态位置

MoonBit 目前已有 `vectie/lunanexa` 这类完整产品控制面和 `vectie/moonflow` 这类持久化编排引擎，但缺少一个能同时被这些宿主复用的纯决策内核。每个控制面若自行实现 diff、依赖排序、风险策略、预算、过期状态保护和审计，容易出现行为不一致，且必须依赖真实集群才能测试。OrbitOps Plane 只拥有执行前的可验证决策，不拥有资源发现、Executor、数据库、HTTP 服务或 Agent。

## 预期使用场景

1. **依赖感知发布**：宿主给出 `database/primary -> service/api -> worker/jobs`。相同输入必须生成相同顺序，循环依赖直接拒绝；在单资源批次预算下依次执行并形成可回放记录。仓库可运行 `moon run cmd/demo -- rollout`。
2. **配置漂移修复**：比较期望配置与观测配置，只生成必要动作；若观测 generation 落后于计划基线，执行前拒绝旧计划，避免依据过期状态完成变更。仓库可运行 `moon run cmd/demo -- drift`。
3. **故障处置保护**：批量重启、删除和关键资源配置为高风险；核心要求显式审批，并在执行器返回失败后停止后续操作。每次策略决定、审批、反馈和终止都有稳定审计事件。仓库可运行 `moon run cmd/demo -- incident`。

## 与 LunaNexa 的对比和协作

LunaNexa 是模型即服务与硬件集群产品控制面，负责节点清单、运行时适配、部署/放置/回滚、API、持久化和控制台。OrbitOps Plane 不复制这些职责，也不接收模型、节点或真实凭据；它只把“期望状态到变更计划”抽成一个可单元测试的 MoonBit 内核。LunaNexa 或其他宿主可继续拥有资源状态、执行方式和交付策略，同时复用本库的稳定排序、风险审批、预算、过期保护和审计重放。MoonFlow 负责 durable execution 和外部效果闭环，本库同样不实现调度、重试或持久化。

## 核心功能与交付

- 类型安全的资源、期望状态、观测状态、操作、计划和执行反馈模型。
- 确定性 `compute_diff`，支持创建、更新、扩缩容、重启、删除和未知动作 fail-closed。
- 依赖图校验、强连通循环拒绝、稳定的依赖优先和删除反向排序。
- 可解释安全策略、风险分级、关键资源保护、审批状态机和变更预算。
- generation 保护、重复反馈拒绝、调和生命周期和可重放审计事件。
- 内存执行器与三个端到端示例，当前 72 个测试，CI 检查格式、构建、测试和生成接口。
- 采用 Apache-2.0，发布目标是 mooncakes.io 模块 `caassien/orbitops_plane`。

## 工程边界与技术理解

计划生成必须保持纯函数和确定性：输入数组顺序不能改变结果，独立资源按稳定 key 排序，依赖边统一采用 `(dependency, dependent)` 语义。执行采用“计划、校验、执行、反馈”四阶段，执行前再次校验 generation；高风险策略先于执行器生效。核心不提供服务器、远程 Agent、SSH/Kubernetes SDK、持久化数据库、UI、监控系统或大模型自动执行，也不承诺替代 Terraform 或 Kubernetes Controller。

## 验收标准

1. 三个 demo 与 72 个测试可复现，核心路径均有失败场景覆盖。
2. 相同输入和不同输入排列产生相同计划；循环依赖、过期计划和重复反馈必须显式失败。
3. 高风险操作在无审批时不得进入执行；执行失败后不得继续后续动作。
4. 每次允许、拒绝、审批、执行反馈和终止均可从审计流重放得到相同状态。
