# OrbitOps Plane 与 KubeMoon 能力边界审计（阶段一）

## 范围与判定方法

- 审计基线：OrbitOps Plane [`f027b569`](https://github.com/caassien/orbitops-plane/commit/f027b5690b326c36d5d20a06bc4db4643c1ff5b3)；KubeMoon [`16171c38`](https://github.com/cxh04/KubeMoon/commit/16171c3898db8bbc66f04f801eb114b68626a085)。比较的是这两个版本的公开源码、README、测试和公开接口；KubeMoon 未提交生成的 `.mbti`，因此以 `pub` 声明和调用测试核对 API。此文不推断其他版本或 MoonFlow、LunaNexa 的实现。
- “已实现”指源码中有可调用实现，并以相关测试或真实调用路径佐证；“部分”指有相近机制但不满足该行完整语义。“未见”只表示本次审计版本的源码、公开接口和测试中未找到，不等于对生态或未来版本作不存在的断言。
- KubeMoon 的 `ConfigMirror` 是将一个源 ConfigMap 同步到多个目标命名空间的具体控制器；OrbitOps 的输入由宿主提供，当前模型固定为 `version / replicas / config_fingerprint / enabled / healthy`，不是任意 Kubernetes 对象模型。证据分别见 [KubeMoon spec](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/configmirror/spec.mbt)、[reconciler](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/operator/reconcile.mbt#L217-L320) 与本仓库 [`model.mbt`](../model.mbt)、[`resource_plan.mbt`](../resource_plan.mbt)。

| Desired/Observed 差异 | **已实现于 ConfigMap 特例**：内容哈希、归属 UID、创建/替换/不变/冲突；见 [`plan_target`](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/configmirror/plan.mbt#L68-L108) 及 [测试](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/configmirror/plan_test.mbt#L18-L37)。 | **已实现于固定资源模型**：创建、更新、伸缩、重启、删除；见 [`compute_diff`](../diff.mbt) 及 [`diff_test.mbt`](../diff_test.mbt)。 | **实质重叠**在“比较后选择动作”；两者输入模型和适用范围不同。不能把字段比较单独宣称为独有价值。 |
| 调谐循环 | **已实现真实控制器**：WATCH 事件驱动、HTTP 写入、状态和 finalizer；见 [scheduler](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/controller/scheduler.mbt)、[reconciler](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/operator/reconcile.mbt#L217-L320) 与 [HTTP 调和测试](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/operator/reconcile_test.mbt#L20-L98)。 | **部分**：[`controller.mbt`](../controller.mbt) 提供单个计划的纯内存生命周期与反馈转移；[`testing/executor.mbt`](../testing/executor.mbt) 仅模拟执行，无持续观察或真实副作用。 | 术语与阶段有重叠，但执行职责不同；对外宜称“计划评估/反馈状态”，避免暗示另一个 Controller。 |
| 任务队列与重试 | **已实现**脏键合并、指数退避、失败重入，及 410 重新 LIST；见 [queue](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/queue/queue.mbt#L51-L105)、[runtime](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/runtime/driver.mbt#L23-L110)、[queue 测试](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/queue/queue_test.mbt)。 | **未实现**持久或运行时队列；失败后可由调用方传入新快照调用 [`replan_remaining`](../resource_plan.mbt)，但这不是自动重试。 | KubeMoon 能力；OrbitOps 不复制。 |
| 跨资源依赖规划 | **部分**：`ConfigMirror` 把源 ConfigMap 同步到多个目标，并按目标循环处理；[spec](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/configmirror/spec.mbt)、[reconciler](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/operator/reconcile.mbt#L275-L320)。公开源码未见任意资源 DAG、拓扑排序或依赖批次 API。 | **已实现**依赖校验、确定排序、删除逆序、传递依赖跨批次隔离；见 [`dependency.mbt`](../dependency.mbt)、[`planner.mbt`](../planner.mbt)、[`budget.mbt`](../budget.mbt) 及 [`resource_plan_test.mbt`](../resource_plan_test.mbt)。 | OrbitOps 当前最明确的**互补候选**：跨资源计划约束；限于比较过的 KubeMoon 版本，不声称生态唯一。 |
| 状态快照前提 | **已实现 Kubernetes 集合版本**：分页 LIST 保持同一 `resourceVersion`，WATCH 从该版本续接；见 [ListSnapshot](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/object/list.mbt#L1-L48)、[driver](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/runtime/driver.mbt#L23-L110) 及 [分页测试](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/runtime/driver_test.mbt)。 | **部分**：`Plan.baseline_generation` 与 `ObservedState.generation` 是数字，但 [`build_resource_plan`](../resource_plan.mbt) 分别接收观测数组和代数，未验证各观测来自同一快照，也未将各状态代数与计划前提绑定；见 [`model.mbt`](../model.mbt)、[`resource_plan_test.mbt`](../resource_plan_test.mbt)。 | KubeMoon 负责获取一致观察；OrbitOps 的“完整同代快照”目前是调用方契约，尚非可验证保证。 |

| 审批与风险策略 | **未见通用计划审批 API**；具体控制器通过所有权冲突、缺失源和 HTTP 错误停止并上报状态；见 [plan](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/configmirror/plan.mbt#L68-L108)、[reconcile](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/operator/reconcile.mbt#L217-L320)。 | **已实现固定规则**：未知动作拒绝、预算冲突拒绝、删除/重启/关键资源要求审批，且有批准/拒绝转移；见 [`policy.mbt`](../policy.mbt)、[`controller.mbt`](../controller.mbt)、[`policy_test.mbt`](../policy_test.mbt)。 | OrbitOps 可复用的策略原语；当前规则固定，不能称为可配置策略语言或外部审批服务。 |
| 计划安全性验证 | **部分**：具体操作校验目标身份、归属、版本，并依赖 Kubernetes 写入时检查冲突；见 [plan](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/configmirror/plan.mbt#L68-L108) 与 [client 请求测试](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/client/client_test.mbt)。 | **部分**：依赖、预算、过期、策略分散在多个函数，公开 [`pkg.generated.mbti`](../pkg.generated.mbti) 没有接受整套输入并返回 `Valid / Invalid / Stale` 与违规列表的独立入口。 | **双方均未实现完整的通用 Plan Validation API**；这是下一阶段需要实际交付的差异点，不能将现有零散门禁包装为已完成。 |

## 重叠判断与重构建议

1. **保留跨资源决策内核，收窄产品定位。** `compute_diff`、生命周期、过期拒绝本身与 KubeMoon 的 ConfigMap 控制器已有交集；应把可独立调用的依赖计划、批次约束、策略解释和后续计划验证作为主入口。保留纯内存状态转移用于决策，但 README/申报书不宜称它是完整控制平面或真实调谐器。依据：上表“差异”“调谐循环”“跨资源依赖规划”行。
2. **先补可验证的计划前提与统一验证结果。** 设计明确的快照 token/来源及资源级版本前提，验证观测集与计划的关系；输出独立的 `Valid / Invalid / Stale`、全部违规、资源/动作引用和解释。现有 `baseline_generation` 由调用方单独传入，公开 API 只能逐项抛错；不得在文档中声称已经验证“完整同代快照”或拥有完整 Plan Validation。依据：[`build_resource_plan`](../resource_plan.mbt)、[`freshness.mbt`](../freshness.mbt)、[`pkg.generated.mbti`](../pkg.generated.mbti)。
3. **将 KubeMoon 作为状态提供方而非被替代者。** 最小适配可以从公开的 [`DynamicObject::raw/name/namespace_name/resource_version`](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/object/object.mbt#L66-L93) 和 [`ListSnapshot::resource_version/items`](https://github.com/cxh04/KubeMoon/blob/16171c3898db8bbc66f04f801eb114b68626a085/object/list.mbt#L11-L21) 读取测试数据，再显式映射到 OrbitOps 输入；行动结果交还模拟宿主。OrbitOps 的 `ResourceId` 只有 kind/name 且 `ResourceSpec` 为固定字段，命名空间、任意 JSON 与字符串 `resourceVersion` 尚无无损直连，适配前必须定义映射和拒绝条件。**本阶段未完成集成。**
4. **验证真正的跨平台复用。** 后续用同一公开 API 做 KubeMoon 测试资源、多服务发布和非 Kubernetes 配置变更；加入输入排列不变性、传递依赖、部分成功、无关资源变化及未知状态的独立调用测试。当前 [`resource_plan_test.mbt`](../resource_plan_test.mbt) 证明若干依赖场景，但不等于外部项目已复用。
5. **降低重复实现的扩张优先级。** 队列、退避、LIST/WATCH、Kubernetes 资源发现和 HTTP 执行已有 KubeMoon 源码与测试支持；本库继续以纯决策/验证接口为界，不增加这些运行时组件。`testing/executor.mbt` 仅作为测试夹具保留。依据：上表“状态获取”“任务队列”“执行反馈”行。

阶段一已完成源码对照与重构建议；阶段二及之后的接口、示例、测试和申报材料修改须在确认定位后实施。本次审计不把“本比较版本未见”提升为全生态独有结论。
